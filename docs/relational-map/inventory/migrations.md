# Inventory — migrations

Every SQL migration, in the order they apply. The game's own tables live at the top of `migrations/`; the platform sign-in schema lives in `migrations/auth/`.

- **0007_tournaments** (`migrations/0007_tournaments.sql`): WP-7: server-verified tournaments and the database-backed signaling relay. Postgres and PGLite compatible, idempotent.

- **0008_social** (`migrations/0008_social.sql`): WP-8: friends, invites, presence, teams and the results that feed trophies. Postgres and PGLite compatible, idempotent.

- **0009_accounts** (`migrations/0009_accounts.sql`): WP-9: the game's own accounts, family profiles and cloud saves — separate from the platform's Better Auth schema. Idempotent.

- **0010_friend_requests** (`migrations/0010_friend_requests.sql`): WP-10: friend requests, blocking, player-name handles and email invites. Postgres and PGLite compatible, idempotent.

- **0011_test_phase** (`migrations/0011_test_phase.sql`): WP-13: the test-phase auto-reset's tiny key-value table; the build_epoch row remembers which build last wiped progress.

- **0012_save_backups** (`migrations/0012_save_backups.sql`): Clear-my-data backups: one row per profile holding every cloud save it had when it cleared, kept for the restore window. Postgres and PGLite compatible, idempotent.

- **0013_fight_queue** (`migrations/0013_fight_queue.sql`): The fish-fight matchmaker's tables: one row per waiting angler, and the pairs the server has made, held until both sides pick them up. Postgres and PGLite compatible, idempotent.

- **0001_auth** (`migrations/auth/0001_auth.sql`): The platform's Better Auth schema (identity and sessions for the sandbox sign-in). Generated by the Better Auth CLI — do not edit by hand.
